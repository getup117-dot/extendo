# Beybe Radar（ベイブレーダー） 引き継ぎ

ベイブレーダーの現在地や出没予定を地図で探し、対戦に参加するモバイル向けWebアプリです。このZIPは試用版 v6 のソースと公開準備に必要なファイルを収録しています。

## Claudeへ渡す依頼文

> このZIPの Beybe Radar を引き継いでください。まずデモを起動して、地図・予定登録・参加・プロフィール編集が動くことを確認してください。その後、SupabaseとHTTPSホスティングをつないで、2アカウントとiPhone Safariで実際に動作確認してください。公開先と公開範囲は私に確認してください。

## ファイル

| パス | 用途 |
|---|---|
| `beyspot/` | 公開用の静的ソース。入口は `index.html`。ビルド不要 |
| `supabase/schema.sql` | DBのテーブル、既存データ向けの追加列、RLS、Realtimeの設定 |
| `outputs/Beybe_Radar_preview.html` | v6と同じ試用版を1ファイルにまとめたもの |
| `work/` | 試用HTMLの生成と自動テスト |

## デモを開く

展開した `Beybe_Radar/` で実行します。

```sh
python3 -m http.server 8766 --directory beyspot
```

ブラウザで [http://localhost:8766/](http://localhost:8766/) を開きます。地図タイルと住所検索はネット接続が必要です。デモの人物とサンプル予定は架空で、登録やプロフィール変更は端末のブラウザ内に保存されます。「出没予定」→「今日」から初心者歓迎のフリーバトルを試せます。iPhoneでLAN上のHTTP試用版を開いた場合は、地図タップや場所検索で地点を選びます。

## 本番接続

1. 使用するSupabaseプロジェクトのSQL Editorで `supabase/schema.sql` を実行します。既存DBに適用する場合は、テスト用プロジェクトで追加列とポリシーの影響を先に確認します。
2. `beyspot/config.js` の `previewOnly` を `false` にし、`supabaseUrl` と `supabasePublicKey` を指定します。ブラウザに置くキーは公開用のPublishableキー、または旧anonキーを使用します。
3. `beyspot/` を公開ディレクトリに指定し、HTTPSで配信します。Netlifyなどの静的ホスティングを選べます。
4. Supabase AuthのサイトURLとリダイレクト許可リストに利用するHTTPSのURLを登録します。画面から発行したログインメールで、同じブラウザに戻って認証が完了することを確認します。
5. 現行のRLSでは登録済みユーザー同士が共有中の位置・予定・参加情報を閲覧できます。公開前に、一般登録か招待制かを確認します。地図・住所検索の配信先は、想定利用規模に合わせて確認します。

## 実機で確認すること

- iPhone Safariで地図検索、地点の選び直し、保存、予定の作成と編集。地点を秋葉原から新宿に変え、案内リンクも新宿を指すことを確認。
- 2アカウントでログインし、片方の予定作成、参加・取り消し、位置共有・停止が相手に反映されることを確認。
- 未ログインで共有情報が見えず、別のアカウントが他人の予定を編集・削除できないことを確認。
- HTTPS上のiPhoneでGPSの許可・拒否、概略／詳細、共有停止後と期限後の表示を確認。
- プロフィールの仮ランクと「対戦歓迎」、当日のスタジアム（主催者持参・店舗・持参募集）が地図と一覧で確認できること。

試用版では自動テスト23項目と、会場の選び直し・別タブへの上書き・日付をまたぐデモ予定の再現テストを確認済みです。Supabaseに接続した2アカウントでの同期と、iPhone実機の表示・GPSは公開前に確認してください。

## 自動テスト

展開したルートで実行します。試用版は同梱済みです。コードを更新した場合は、試用用の設定でHTMLを再生成してからテストします。

```sh
python3 work/build-preview.py
npm --prefix work install
npm --prefix work test
```

テストの依存関係はNode.js 20以上が必要です。サイトの実行にはNode.jsやnpmは不要です。
